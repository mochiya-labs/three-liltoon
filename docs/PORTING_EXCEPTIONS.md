# Porting exceptions

The upstream submodule is unchanged. All exceptions below live in maintained compatibility code or deterministic generated output.

1. **Web vertex fields.** `tools/shader-build/generate-web-appdata.ts` copies upstream `lil_common_appdata.hlsl` into a generated build artifact and injects Three-compatible `skinIndex` and `skinWeight` fields. `skinIndex` is a float attribute because Three supplies integer component buffers through its normal float attribute path; the compatibility function converts it to `uint4` before bone lookup.
2. **Scene-light mutation.** Upstream `LIL_FORCE_SCENE_LIGHT` can assign material globals, which Vulkan uniform blocks forbid. Wrappers replace that macro with a no-op and the private renderer context applies the equivalent force-scene-light values before upload.
3. **Matrix convention.** Cross-compiled GLSL retains HLSL row-vector expressions. Runtime object, camera, bind, light-shadow matrices are transposed during upload. This is an ABI rule, not a vendor edit.
4. **WebGL varying names.** SPIRV-Cross names separate stage interfaces `out_var_*` and `in_var_*`. ESSL 3.00 links varyings by name, so the generator deterministically renames fragment inputs to their vertex output names. A compiler test verifies every pair.
5. **GLSL version placement.** Standalone generated files keep `#version 300 es` for glslang. Three prepends material defines, so `LilToonMaterial` removes that first directive and sets `glslVersion = GLSL3`, allowing Three to place it first.
6. **Shadow ABI.** Unity shadow macros are replaced by one Three directional-light matrix and RGBA-packed shadow texture with 2×2 PCF. Three's depth bias and receiver normal bias are applied; cascades, VSM, and shadow radius/intensity parity are not reproduced.
7. **Lighting ABI.** Unity/URP/HDRP lighting is represented by the first visible Three `DirectionalLight` plus ambient/hemisphere color and a simple SH constant term. Additional lights, lightmaps, probes, and Unity attenuation modes use neutral fallbacks.
8. **Environment ABI.** A public `THREE.CubeTexture` is sampled directly. The adapter does not access private PMREM/equirect renderer state and therefore cannot reproduce Unity reflection-probe blending.
9. **Texture safety.** Absent 2D resources receive semantic neutral pixels. Cube samplers receive Three's neutral cube binding. Incompatible 2D/cube textures are ignored to avoid a WebGL `INVALID_OPERATION`; active mismatches are available through `getWarnings()` and loader warning callbacks.
10. **Deformation.** Bone matrices use Three's public bone texture and bind matrices. Position/normal morphs reuse Three's renderer-owned texture/weight uploads and installed shader chunks before the compiled lilToon vertex entry. There is no package-defined morph cap or CPU overflow; standard Three/WebGL resource limits and morph-geometry lifecycle rules apply. See [Three.js morph integration](ARCHITECTURE.md#threejs-morph-integration).
11. **Pass architecture.** Outlines are a package-owned child draw and shadow casting uses Three depth/distance materials. Explicit refraction, fur, and gem pass constructors throw unsupported-feature errors. Loading a material that requests an unsupported Unity shader family instead warns and retains the standard forward fallback; it does not reproduce that special pass.
12. **Unsupported platform facilities.** Instancing, stereo/WebXR, VRC Light Volumes, AudioLink, tessellation, Unity grab passes, and pipeline-specific editor facilities are not emulated.
13. **Sampler-budget profiles.** Three allocates texture units across the linked program and warns when allocation reaches the renderer's 16-unit limit. Avatar vertex deformation consumes two samplers (bone and morph data), leaving fourteen for the lilToon fragment shader. Generated, material-selected profiles trade unused feature families instead of compiling one maximal shader: ordinary, dissolve-noise, MatCap-mask, layered-MatCap, surface-control, and layered-surface-control. Layered profiles preserve the Main Color 2nd/3rd textures and blend masks; MatCap profiles preserve both MatCap masks and custom normals; surface-control profiles preserve metallic, smoothness, and reflection-color textures. The layered-surface-control profile additionally preserves Main Color 2nd when the primary and MatCap normal slots reference the same glTF texture object; one sampler is then shared while every slot keeps its own `_ST` and scale uniforms. Compiler tests count the combined vertex/fragment sampler set and fail above sixteen.

`shader/patches/` remains free of vendor patches. If a future upgrade appears to require one, first determine whether a wrapper, compatibility definition, or generated transform can express the change, then document the exception and add a regression test.
